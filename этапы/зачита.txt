Проект HobbyMatch Bot. Это ВК-бот. Его главная задача — помогать людям находить других людей с такими же увлечениями и интересами. Проще говоря, если ты, например, увлекаешься скейтбордингом и живёшь в Москве, бот найдёт тебе других скейтбордистов из Москвы, покажет их анкеты, и ты сможешь с ними познакомиться.

Проект состоит из двух основных частей: самого бота и внутреннего API-сервера. 
Бот написан на Python с использованием библиотеки vk_api. Она позволяет подключаться к LongPoll — это такой механизм ВКонтакте, который в реальном времени присылает боту все новые сообщения. Бот постоянно «слушает» входящие сообщения, и как только кто-то пишет ему в личные сообщения, он обрабатывает текст и решает, что ответить. 
Для управления диалогом я реализовал FSM(Это значит что бот запоминает, на каком шаге находится пользователь). Например, если пользователь начал регистрацию и ввёл имя, бот переключает его в состояние «ожидание хобби». Пока пользователь не завершит текущий шаг, бот не перейдёт к следующему. Это очень удобно, потому что бот всегда знает контекст беседы и не путается.
Регистрация устроена как последовательность шагов: сначала пользователь вводит имя, потом своё хобби, город, уровень мастерства (новичок, любитель, профи или эксперт), указывает, есть ли у него своё снаряжение, пишет небольшое описание о себе и в конце прикрепляет фотографию. Бот проверяет каждое поле — например, имя не должно быть слишком длинным и не может содержать цифры. Когда пользователь отправляет фото, бот не просто сохраняет ссылку на него — он асинхронно скачивает изображение к себе на сервер с помощью библиотек httpx и aiofiles, а в базу данных записывает только имя файла. 
Внутренний API-сервер написан на FastAPI. Его задача — принимать запросы от бота, обрабатывать их и работать с базами данных. Здесь я использую две базы данных: основную и кэширующую.
Основная база данных — PostgreSQL. В ней хранятся все анкеты пользователей и лайки. Для работы с ней я использую SQLAlchemy — это такая штука, которая позволяет не писать SQL-запросы вручную, а работать с базой данных через Python-объекты. Для каждой анкеты в базе хранятся: уникальный идентификатор пользователя ВК, имя, хобби, город, уровень мастерства, наличие снаряжения, биография, путь к фотографии и счётчик просмотров. Для лайков есть отдельная таблица, где записано, кто и кому поставил лайк.
Вторая база данных — Redis. Она используется для кэширования. Дело в том, что к PostgreSQL идёт много запросов, особенно часто бот запрашивает анкету текущего пользователя. Чтобы не нагружать базу лишний раз, анкета сохраняется в Redis на 10 минут. Когда бот запрашивает данные, API сначала проверяет, есть ли они в Redis. Если есть — возвращает их мгновенно, без похода в PostgreSQL. Если нет — тогда идёт запрос в основную базу. Это заметно ускоряет работу бота.
Когда пользователь нажимает кнопку «Найти партнёра», бот отправляет запрос в API на специальный эндпоинт. API берёт из базы город и хобби текущего пользователя, а затем ищет всех других пользователей, у которых совпадают оба этих параметра. Из результатов поиска автоматически исключается сам пользователь, чтобы он не нашёл сам себя. Если подходящих кандидатов нет, бот сообщает об этом. Если есть — пользователь может листать анкеты кнопкой «Следующий», ставить лайки или сразу перейти по ссылке на страницу человека в ВК и написать ему.
Также я реализовал подсчёт просмотров. Каждый раз, когда пользователь открывает чью-то анкету в режиме поиска, API увеличивает счётчик просмотров у владельца анкеты на единицу. Для лайков работает отдельная система — при нажатии на кнопку «Лайк» запись о симпатии сохраняется в базе. Пользователь может зайти в свой профиль и увидеть, кто его лайкнул.
Вся система работает внутри Docker-контейнеров. У меня четыре контейнера: PostgreSQL (база данных), Redis (кэш), core_api (FastAPI-сервер) и bot (сам бот). Они связаны между собой через внутреннюю сеть Docker и общаются по HTTP.
